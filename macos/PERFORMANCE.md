# LeonBook 性能基线与预算

更新日期：2026-09-06。基线设备为 Apple Silicon `arm64`、Swift 6.3.3。所有验证均通过命令行测试与构建完成，不启动应用。

## 测量方法

```zsh
macos/scripts/test-app.sh
macos/scripts/benchmark-performance.sh
macos/scripts/build-app.sh
```

`benchmark-performance.sh` 使用 Release 优化级别运行七组基准：文章投影、智能集合公式汇总、微博时间戳跨投影复用、文章标签切换、图谱交互、长文双链补全、资源侧栏导航。前五组采用 10,000 条数据；长文补全使用约 100 万 UTF-16 字符的正文；资源侧栏采用 100 个文件夹、10,000 篇文章。文章过滤逐轮交替运行改造前算法与当前投影算法，并在相邻轮次交换先后顺序，避免缓存预热固定偏向某一实现。标签切换基准使用 10,000 篇文章、16 个已打开的大正文标签，并另外模拟 48 个标签的 20 轮标题重算。过滤与公式汇总报告四次采样中的最短值；投影建立记录一次完整建立，随后在旧投影仍存活时建立新投影并读取进程 RSS 增量模拟重建峰值。绝对耗时和内存用于本机回归，算法前后比值用于跨机器判断。

可通过 `LEON_BOOK_TEST_FILTER=Graph macos/scripts/benchmark-performance.sh` 单独执行名称包含 Graph 的测试与图谱基准。图谱基准使用 10,000 个节点、9,999 条有向边和 500 个可见节点；在两轮交替采样中分别执行 8 次原始投影和当前交互入口，报告较短一轮的单次平均耗时。路径复用另用 500 个节点的有向链，每轮调用 64 次。两组分别断言前后返回的节点数和路径跳数相同，并要求重复调用降低至少 90% 的计算耗时；完整投影结果由功能测试另行比对。这不代表整个画布的渲染耗时。

| Release 应用打包 | 71.96–129.57 s，签名与校验通过 | 从全目标构建失败恢复为成功 |

当前投影仅在文章或微博数据变化时重建。无筛选文章列表直接返回底层数组；普通输入先在可取消的 `Task.detached` 中匹配预先规范化的摘要，非 debounce 刷新则直接请求 FTS，避免串行等待本地扫描；FTS 已完成时只按 slug 集合匹配。标签、文件夹、状态、最近文章、微博标签、月份和时间线都复用已建立的索引。文章投影只保留一份完整摘要，slug 和状态统计使用整数索引或计数；统一的重建协调器以 generation 防止较旧投影覆盖新数据，确定性 barrier 测试覆盖重建期间的浏览量合并。

智能集合公式复用有上限的分词缓存、日期解析缓存和线程安全的日期格式器缓存；Property 与公式键优先走精确字典/字符串匹配，仍保留大小写不敏感兼容路径。汇总改为流式聚合，不再为每组文章分配完整值数组。大表从整组 `Grid` 改为惰性行栈，初始展示不再实例化全部单元格。共享时间戳缓存让微博 facet、时间线和其他消费者复用 ISO8601 解析结果；微博分页仍先提交首屏，再刷新全量 facet，且时区或区域设置变化会主动失效依赖日历的投影。

标签栏标题通过文章投影的 slug 索引做常数时间查询，不再让每个标签扫描整库；横向标签栏只创建可见项。已访问正文放入 24 项、32 MiB 的有界缓存，并以 workspace generation、更新时间和阅读量校验，避免跨工作区或旧版本复用。标签历史的 JSON 编码和 `UserDefaults` 写入采用 150 ms 合并并移出主线程；同一次切换也不再重复持久化。编辑器双链建议使用惰性过滤，找到 8 项后立即停止扫描。

## 2026-09-05：图谱交互

原图谱视图会在摘要计数、空状态、画布尺寸、路径高亮和变化监听中重复投影，每次都遍历并排序整个文章库。新增测试在修复前确认：10,000 节点单次重复投影耗时 18.606 ms，投影复用断言以及 1 ms / 90% 性能预算均失败。

本轮完整 Release 基准中的同进程对照结果：

| 项目 | 未缓存 | 复用缓存 |
| --- | ---: | ---: |
| 10k 节点、相同筛选获取投影一次 | 18.461 ms | 0.000505 ms |
| 500 节点、相同起终点获取有向路径一次 | 0.509 ms | 0.000020 ms |

两项重复计算耗时均降低超过 99.99%。首次图谱投影建立为 21.546 ms，缓存只改善之后的数据与筛选未变的重复读取。

图谱现在每轮视图更新只读取一次投影，并在窗口模型中缓存最近一组筛选结果。节点或边被替换时立即清空；筛选条件或区域设置变化时重建。缓存仅保留最多 500 个可见节点及其连线，不保留额外一份完整图谱，不在拖动时比较整库数组。最近一对起终点的有向路径（包括无路径结果）随投影复用；逐节点高亮判断复用集合，避免扫描整条路径。

功能回归覆盖四类筛选条件、拖动/缩放/路径输入后的投影复用、仅连线变化、节点数量和 slug 不变的元数据变化、工作区清空、窗口隔离，以及路径方向和起终点变更。首次建立投影和改变筛选条件仍同步执行；本轮不包含实际画布帧率测量。

`macos/scripts/test-app.sh` 通过：101 个单元测试、7 组模块测试、原生结构检查、存储检查。`macos/scripts/benchmark-performance.sh` 默认运行的 5 组性能基准全部通过；既有文章投影、公式、微博时间戳和标签切换预算均未回归。

## 2026-09-05：文档编辑与写作

通过 `LEON_BOOK_TEST_FILTER=Writing macos/scripts/benchmark-performance.sh` 单独运行写作测试和基准。补全基准在 20,000 行混合中英文 Markdown 后追加一个普通段落，共 1,000,004 个 UTF-16 字符；旧算法复制光标之前的正文并向前查找双链，新算法只检查当前行。两轮采样交换执行顺序，每轮各运行 80 次，报告较短一轮的单次平均耗时；均断言普通段落不触发补全。修复前实际入口单次耗时 32.665 ms，0.5 ms 预算和相对收益断言均失败。

完整 Release 基准的同进程对照为 **33.413 ms → 0.000423 ms/次**，这部分检测耗时降低超过 99.99%。这是普通段落补全检测的结果，不代表整次按键处理时间；单行极长时查询仍随当前行长度增长。

除了限制双链扫描范围，双链与斜杠菜单仅在查询内容改变时发布更新，普通光标移动不再发布重复的空查询。块编辑器仅在文字或排版设置改变时改写样式，仅在文字、排版或容器宽度改变时强制布局。

中文等输入法的组合态由输入法处理：组合期间暂停草稿写回、样式重置、补全和块级回车/退格命令；确认后继续同步正文。正文编辑视图按草稿身份重建，并在拆除时解除代理，避免把旧文档的输入状态带进新文档。语法说明改为默认收起的“写作语法参考”，保留中英文标签和全部说明内容。

确定性回归使用不创建窗口的 `NSTextView`、实际编辑协调器及文本存储样式修改计数，覆盖重复查询通知、中文/emoji/CRLF 双链范围、非法选区、20 次无变化的文本块刷新、排版设置失效、模拟组合态和确认后的正文同步。没有启动应用，尚未现场验证真实输入法候选窗、视觉布局或端到端按键延迟。

`macos/scripts/test-app.sh` 通过 103 个单元测试、7 组模块测试、原生结构检查和存储检查；`macos/scripts/benchmark-performance.sh` 的 6 组性能基准全部通过。

## 2026-09-06：资源侧栏与文章定位

原资源查询每次都递归展开目录树；选取 100 个资源时，还会为每个 ID 再展开一次整棵树。定位文章后又从根节点搜索祖先，移动菜单也重复计算可用目录。修复前通过 `LEON_BOOK_TEST_FILTER=WorkspaceResourceInteractionBenchmark macos/scripts/benchmark-performance.sh` 实测：10,000 篇文章中选取 100 个资源耗时 347.206 ms，定位文章及其父目录耗时 4.171 ms，两项绝对预算及 90% 相对收益断言均失败。

窗口模型现在为当前目录树惰性建立导航索引。单次遍历生成目录顺序、ID / 文章 slug 索引及父节点整数偏移；多选仅查询并排序选中项，祖先查询仅沿父链访问。索引与目录树共享节点的子数组，可用目录列表首次需要时才生成并缓存。任何目录树赋值或嵌套变更都会丢弃旧索引，下一次访问再建立；空多选不会触发建立。

完整 Release 基准中的同进程对照结果：

| 项目 | 原完整遍历 | 当前索引 |
| --- | ---: | ---: |
| 10k 文章，选取 100 个资源一次 | 237.105 ms | 0.009 ms |
| 10k 文章，定位文章及其父目录一次 | 2.978 ms | 0.000231 ms |
| 10k 文章，首次建立导航索引 | — | 5.333 ms |

两条重复查询路径耗时均降低超过 99.99%；首次建立成本单独列出，不包含在复用耗时内。

通过 `LEON_BOOK_TEST_FILTER=WorkspaceResource macos/scripts/benchmark-performance.sh` 运行针对性验证。基准包含 100 个文件夹、10,000 篇文章；多选每轮执行 3 次，文章定位每轮执行 100 次，两轮交换新旧算法的先后顺序并报告较短一轮的平均值。多选逐次核对全部结果及顺序，定位核对返回的祖先数量；完整父链、混合附件、普通页面与 index 页面子目录、中文路径、同 ID 元数据更新、嵌套移动 / 删除 / 重排、缓存释放及窗口隔离由功能测试覆盖。

首次导航索引建立及首次生成移动目标目录仍是同步工作。这组基准测量数据查询路径，不包含目录扫描、原始树建立或 SwiftUI 侧栏绘制耗时。

`macos/scripts/test-app.sh` 通过 105 个单元测试、7 组模块测试、原生结构检查和存储检查；`macos/scripts/benchmark-performance.sh` 的 7 组性能基准全部通过。既有文章投影、公式、微博时间戳、标签切换、图谱和写作预算均未回归。未启动应用或游戏。

## 回归判定

- Release 基准超过任一绝对预算，或者新算法没有分别比旧算法快 90%（无筛选）、25%（后台摘要匹配）和 50%（已解析搜索），视为性能回归。
- 10k 算术公式超过 80 ms、日期公式超过 120 ms，或已解析时间戳进入时间线投影超过 120 ms，视为性能回归。
- 已访问标签切换平均超过 0.25 ms，或 48 个标签的 20 次标题重算超过 5 ms，视为交互性能回归。
- 图谱投影复用超过 1 ms、路径复用超过 0.1 ms，或任一项未比未缓存实现快至少 90%，视为图谱交互性能回归。
- 百万字符正文的普通段落双链检测超过 0.5 ms，或未比正文前缀扫描快至少 75%，视为写作交互性能回归。
- 10k 资源导航索引建立超过 50 ms、多选 100 项超过 1 ms、定位文章及其父目录超过 0.1 ms，或后两项未比原完整遍历快至少 90%，视为资源侧栏性能回归。
- 基准脚本是显式运行项，不放进普通测试，避免日常功能测试受机器负载影响。
- 冷构建耗时受 Swift 编译缓存影响，只记录趋势；运行时对照始终使用同进程的旧/新算法结果。
