# LeonBook 性能基线与预算

更新日期：2026-10-23。基线设备为 Apple Silicon `arm64`、Swift 6.3.3。验证通过命令行测试与构建完成；富文本交互使用离屏 WKWebView，不启动游戏。

## 测量方法

```zsh
macos/scripts/test-app.sh
macos/scripts/benchmark-performance.sh
macos/scripts/build-app.sh
```

`benchmark-performance.sh` 使用 Release 优化级别运行八组基准：文章投影、智能集合公式汇总、微博时间戳跨投影复用、文章标签切换、图谱交互、长文双链补全、资源侧栏导航、阅读页目录复用。前五组采用 10,000 条数据；长文补全使用约 100 万 UTF-16 字符的正文；资源侧栏采用 100 个文件夹、10,000 篇文章；阅读页采用 1,000 个标题和 20 次重复目录读取。文章过滤逐轮交替运行改造前算法与当前投影算法，并在相邻轮次交换先后顺序，避免缓存预热固定偏向某一实现。标签切换基准使用 10,000 篇文章、16 个已打开的大正文标签，并另外模拟 48 个标签的 20 轮标题重算。过滤与公式汇总报告四次采样中的最短值；投影建立记录一次完整建立，随后在旧投影仍存活时建立新投影并读取进程 RSS 增量模拟重建峰值。绝对耗时和内存用于本机回归，算法前后比值用于跨机器判断。

可通过 `LEON_BOOK_TEST_FILTER=Graph macos/scripts/benchmark-performance.sh` 单独执行名称包含 Graph 的测试与图谱基准。图谱基准使用 10,000 个节点、9,999 条有向边和 500 个可见节点；在两轮交替采样中分别执行 8 次原始投影和当前交互入口，报告较短一轮的单次平均耗时。路径复用另用 500 个节点的有向链，每轮调用 64 次。两组分别断言前后返回的节点数和路径跳数相同，并要求重复调用降低至少 90% 的计算耗时；完整投影结果由功能测试另行比对。这不代表整个画布的渲染耗时。

当前投影仅在文章或微博数据变化时重建。无筛选文章列表直接返回底层数组；普通输入先在可取消的 `Task.detached` 中匹配预先规范化的摘要，非 debounce 刷新则直接请求 FTS，避免串行等待本地扫描；FTS 已完成时只按 slug 集合匹配。标签、文件夹、状态、最近文章、微博标签、月份和时间线都复用已建立的索引。文章投影只保留一份完整摘要，slug 和状态统计使用整数索引或计数；统一的重建协调器以 generation 防止较旧投影覆盖新数据，确定性 barrier 测试覆盖重建期间的浏览量合并。

智能集合公式复用有上限的分词缓存、日期解析缓存和线程安全的日期格式器缓存；Property 与公式键优先走精确字典/字符串匹配，仍保留大小写不敏感兼容路径。汇总改为流式聚合，不再为每组文章分配完整值数组。大表从整组 `Grid` 改为惰性行栈，初始展示不再实例化全部单元格。共享时间戳缓存让微博 facet、时间线和其他消费者复用 ISO8601 解析结果；微博分页仍先提交首屏，再刷新全量 facet，且时区或区域设置变化会主动失效依赖日历的投影。

标签栏标题通过文章投影的 slug 索引做常数时间查询，不再让每个标签扫描整库；横向标签栏只创建可见项。已访问正文放入 24 项、32 MiB 的有界缓存，并以 workspace generation、更新时间和阅读量校验，避免跨工作区或旧版本复用。标签历史的 JSON 编码和 `UserDefaults` 写入采用 150 ms 合并并移出主线程；同一次切换也不再重复持久化。编辑器双链建议使用惰性过滤，找到 8 项后立即停止扫描。

## 2026-09-05：图谱交互

原图谱视图会在摘要计数、空状态、画布尺寸、路径高亮和变化监听中重复投影，每次都遍历并排序整个文章库。新增测试在修复前确认：10,000 节点单次重复投影耗时 18.606 ms，投影复用断言以及 1 ms / 90% 性能预算均失败。

本轮完整 Release 基准中的同进程对照结果：

| 项目 | 未缓存 | 复用缓存 |
| --- | ---: | ---: |
| 10k 节点、相同筛选获取投影一次 | 18.461 ms | 0.000505 ms |
| 500 节点、相同起终点获取有向路径一次 | 0.509 ms | 0.000020 ms |

两项重复计算耗时均降低超过 99.99%。首次图谱投影建立为 21.546 ms，缓存只改善之后的数据与筛选未变的重复读取。

图谱现在每轮视图更新只读取一次投影，并在窗口模型中缓存最近一组筛选结果。节点或边被替换时立即清空；筛选条件或区域设置变化时重建。缓存仅保留最多 500 个可见节点及其连线，不保留额外一份完整图谱，不在拖动时比较整库数组。最近一对起终点的有向路径（包括无路径结果）随投影复用；逐节点高亮判断复用集合，避免扫描整条路径。

功能回归覆盖四类筛选条件、拖动/缩放/路径输入后的投影复用、仅连线变化、节点数量和 slug 不变的元数据变化、工作区清空、窗口隔离，以及路径方向和起终点变更。首次建立投影和改变筛选条件仍同步执行；本轮不包含实际画布帧率测量。

`macos/scripts/test-app.sh` 通过：101 个单元测试、7 组模块测试、原生结构检查、存储检查。`macos/scripts/benchmark-performance.sh` 默认运行的 5 组性能基准全部通过；既有文章投影、公式、微博时间戳和标签切换预算均未回归。

## 2026-09-05：文档编辑与写作

通过 `LEON_BOOK_TEST_FILTER=Writing macos/scripts/benchmark-performance.sh` 单独运行写作测试和基准。补全基准在 20,000 行混合中英文 Markdown 后追加一个普通段落，共 1,000,004 个 UTF-16 字符；旧算法复制光标之前的正文并向前查找双链，新算法只检查当前行。两轮采样交换执行顺序，每轮各运行 80 次，报告较短一轮的单次平均耗时；均断言普通段落不触发补全。修复前实际入口单次耗时 32.665 ms，0.5 ms 预算和相对收益断言均失败。

完整 Release 基准的同进程对照为 **33.413 ms → 0.000423 ms/次**，这部分检测耗时降低超过 99.99%。这是普通段落补全检测的结果，不代表整次按键处理时间；单行极长时查询仍随当前行长度增长。

除了限制双链扫描范围，双链与斜杠菜单仅在查询内容改变时发布更新，普通光标移动不再发布重复的空查询。块编辑器仅在文字或排版设置改变时改写样式，仅在文字、排版或容器宽度改变时强制布局。

中文等输入法的组合态由输入法处理：组合期间暂停草稿写回、样式重置、补全和块级回车/退格命令；确认后继续同步正文。正文编辑视图按草稿身份重建，并在拆除时解除代理，避免把旧文档的输入状态带进新文档。语法说明改为默认收起的“写作语法参考”，保留中英文标签和全部说明内容。

确定性回归使用不创建窗口的 `NSTextView`、实际编辑协调器及文本存储样式修改计数，覆盖重复查询通知、中文/emoji/CRLF 双链范围、非法选区、20 次无变化的文本块刷新、排版设置失效、模拟组合态和确认后的正文同步。没有启动应用，尚未现场验证真实输入法候选窗、视觉布局或端到端按键延迟。

`macos/scripts/test-app.sh` 通过 103 个单元测试、7 组模块测试、原生结构检查和存储检查；`macos/scripts/benchmark-performance.sh` 的 6 组性能基准全部通过。

## 2026-09-06：资源侧栏与文章定位

原资源查询每次都递归展开目录树；选取 100 个资源时，还会为每个 ID 再展开一次整棵树。定位文章后又从根节点搜索祖先，移动菜单也重复计算可用目录。修复前通过 `LEON_BOOK_TEST_FILTER=WorkspaceResourceInteractionBenchmark macos/scripts/benchmark-performance.sh` 实测：10,000 篇文章中选取 100 个资源耗时 347.206 ms，定位文章及其父目录耗时 4.171 ms，两项绝对预算及 90% 相对收益断言均失败。

窗口模型现在为当前目录树惰性建立导航索引。单次遍历生成目录顺序、ID / 文章 slug 索引及父节点整数偏移；多选仅查询并排序选中项，祖先查询仅沿父链访问。索引与目录树共享节点的子数组，可用目录列表首次需要时才生成并缓存。任何目录树赋值或嵌套变更都会丢弃旧索引，下一次访问再建立；空多选不会触发建立。

完整 Release 基准中的同进程对照结果：

| 项目 | 原完整遍历 | 当前索引 |
| --- | ---: | ---: |
| 10k 文章，选取 100 个资源一次 | 237.105 ms | 0.009 ms |
| 10k 文章，定位文章及其父目录一次 | 2.978 ms | 0.000231 ms |
| 10k 文章，首次建立导航索引 | — | 5.333 ms |

两条重复查询路径耗时均降低超过 99.99%；首次建立成本单独列出，不包含在复用耗时内。

通过 `LEON_BOOK_TEST_FILTER=WorkspaceResource macos/scripts/benchmark-performance.sh` 运行针对性验证。基准包含 100 个文件夹、10,000 篇文章；多选每轮执行 3 次，文章定位每轮执行 100 次，两轮交换新旧算法的先后顺序并报告较短一轮的平均值。多选逐次核对全部结果及顺序，定位核对返回的祖先数量；完整父链、混合附件、普通页面与 index 页面子目录、中文路径、同 ID 元数据更新、嵌套移动 / 删除 / 重排、缓存释放及窗口隔离由功能测试覆盖。

首次导航索引建立及首次生成移动目标目录仍是同步工作。这组基准测量数据查询路径，不包含目录扫描、原始树建立或 SwiftUI 侧栏绘制耗时。

`macos/scripts/test-app.sh` 通过 105 个单元测试、7 组模块测试、原生结构检查和存储检查；`macos/scripts/benchmark-performance.sh` 的 7 组性能基准全部通过。既有文章投影、公式、微博时间戳、标签切换、图谱和写作预算均未回归。未启动应用或游戏。

## 回归判定

- Release 基准超过任一绝对预算，或者新算法没有分别比旧算法快 90%（无筛选）、25%（后台摘要匹配）和 50%（已解析搜索），视为性能回归。
- 10k 算术公式超过 80 ms、日期公式超过 120 ms，或已解析时间戳进入时间线投影超过 120 ms，视为性能回归。
- 已访问标签切换平均超过 0.25 ms，或 48 个标签的 20 次标题重算超过 5 ms，视为交互性能回归。
- 图谱投影复用超过 1 ms、路径复用超过 0.1 ms，或任一项未比未缓存实现快至少 90%，视为图谱交互性能回归。
- 百万字符正文的普通段落双链检测超过 0.5 ms，或未比正文前缀扫描快至少 75%，视为写作交互性能回归。
- 10k 资源导航索引建立超过 50 ms、多选 100 项超过 1 ms、定位文章及其父目录超过 0.1 ms，或后两项未比原完整遍历快至少 90%，视为资源侧栏性能回归。
- 基准脚本是显式运行项，不放进普通测试，避免日常功能测试受机器负载影响。
- 冷构建耗时受 Swift 编译缓存影响，只记录趋势；运行时对照始终使用同进程的旧/新算法结果。

## 2026-10-22：富文本输入与鼠标交互

使用真实 WKWebView 编辑器做离屏基准，不启动游戏。`testRichArticleLongDocumentTypingWork` 在 2,000 个段落（每段含加粗内容）中间连续输入 12 个字符，计入键盘事件、撤销检查点和编辑通知；`testRichArticlePointerWorkIsFrameBounded` 在 12 列表格中发送 120 次指针移动，等待调度完成，并实际点击增列按钮验证功能。

| 指标 | 修改前 | 修改后（一次本机采样） |
| --- | ---: | ---: |
| 单次输入同步处理平均耗时 | 29.42 ms | 1.42 ms |
| 单次输入同步处理最大耗时 | 45 ms | 4 ms |
| 12 次输入重新清理的 HTML 字符 | 13,002,996 | 1,710 |
| 12 次输入的全文节点查询 | 48 | 0 |
| 120 次鼠标移动的布局边界读取 | 1,438 | 9 |

耗时是合成事件在本机 WebKit 内的同步处理时间，包含浏览器编辑工作，不等同于物理鼠标到屏幕的延迟或整机帧率；构建负载和计时精度会影响结果。回归门禁约束工作量（12 次输入清理量小于 50,000 字符、一次指针事件突发读取布局少于 80 次），不使用易波动的毫秒值判定通过。

正文以顶层块的 DOM 身份缓存清理后的 HTML。MutationObserver 标记文本、属性、结构及重新插入节点的变化，序列化前同步提取尚未投递的记录，防止同一事件内保存旧值。普通输入只清理修改块；结构变化仍运行规范化。完整正文继续立即交给原生模型，避免延迟发布导致保存或切换文章丢失最后一次输入。新增差分测试将缓存输出与完整清理器逐项对照，覆盖颜色、表格、删除、移动、离开文档后修改并重新插入、顶层文本、文章切换和不安全属性清理。

表格悬浮、列宽及图片拖拽、滚动浮层定位按显示帧合并，只处理最新坐标；拖拽结束会先提交最后一个坐标。WebKit 在窗口被遮挡时可能暂停显示帧，因此提供一次性的 48 ms 回退，不进行空闲轮询。普通段落的鼠标移动不安排表格布局工作，高亮取消 120 ms 背景/阴影过渡；表格仅高亮鼠标所在单元格，避免进入表格时重绘所有单元格。

高度通知按帧合并且仅在数值变化时发送；选区中的代码检测限制到选区公共祖先；原生大纲复用现有后台分析结果；编辑器静态 HTML/CSS/JS 资源只加载组合一次。首次打开、跨块结构规范化、完整正文跨桥传输和大表格内部编辑仍有进一步测量空间。本轮没有引入可见区域虚拟化，以保留原生内容编辑、跨段选择及输入法行为。

## 2026-10-23：博客阅读页性能审查

审查范围包括文章列表与搜索、阅读页派生数据、选区评论、图片读取和关系查询。列表已使用摘要查询及后台搜索投影；原生图片管线已有缩略图缓存和解码并发限制。本轮优先处理阅读页中仍存在的重复工作。

阅读页已经取得 `NativeMarkdownArticleDocumentCache` 中的文档，随后却再次调用 `RichArticleDocument.outline` 解析整篇正文。侧栏宽度变化和模型更新均可能重新执行该路径。现在直接复用同一个文档的目录，标题内容、级别和锚点保持一致。`testRichArticleReaderMetadataReuseBenchmark` 用 1,000 个含中文、emoji、组合字符和实体的标题，比较 20 次旧目录解析与缓存文档目录读取，两轮交换顺序并核对完整结果；Debug 本机采样为 **441.717 ms → 0.011708 ms / 20 次**。这是重复派生数据的耗时，首次文档分析仍存在。

阅读模式原本每次 `selectionchange` 都向原生界面发送文字。原生评论准备会提取全文确认选区，并更新评论侧栏，所以鼠标拖选中的中间范围也不断触发 SwiftUI 更新。真实 WKWebView 测试中，120 次合成选区变化发送了 121 次通知（包含浏览器追加的选区事件）。现在拖选期间发送 **0 次**，松开鼠标后发送最终范围 **1 次**；键盘选区同帧合并，相同文字去重。折叠选区后可以重新选择同一段文字，切换文档及窗口失焦会取消待发送任务。回归测试检查实际原生消息及文字内容，并覆盖重复通知、重新选择和切换文章。

另测了正则预编译、直接按 UTF-16 范围提取 HTML 元数据两种改写：约 36 万 UTF-16 字符、1,000 个标题/图片/链接的冷解析没有稳定收益，因此撤回这些生产代码改写，保留原解析实现。

后续值得测量的路径（本轮未改动，尚无收益数字）：

- 富文本中的本地图片通过 `RichArticleMediaHandler` 为每个请求完整读取文件，未复用 `NativeImagePipeline` 的缩略图/并发限制。多张大图场景应先测首屏耗时与峰值内存，再决定请求去重、限流和显示尺寸缓存；原图预览需保留。
- 打开文章时会加载评论和关系，即使关系面板隐藏；`articleRelations` 读取全库摘要并建立链接身份索引。可测量大库切换文章时的查询成本，再考虑按面板需求加载及按数据版本复用索引。
- 搜索界面会取消旧任务并丢弃过期结果，但同步 SQLite 搜索内部没有取消检查。需要用较慢的实际查询确认任务排队成本，再决定是否加入查询中断或更早的取消检查。

上述测试不启动游戏；离屏合成事件和数据操作耗时不代表实际屏幕帧率或鼠标输入延迟。

本轮验证：168 项单元测试通过，新增白板的 `testWhiteboardBundledRuntimeExportsAndReopensOffline` 未能在等待期内初始化离线运行时，构建结束后的独立复测仍失败。该用例加载独立白板页面，不经过本轮修改的阅读页目录或选区通知路径；本轮未修改白板实现。8 组模块测试、存储检查及 Release 打包通过。阅读/编辑与 HTML 元数据相关的 27 项普通回归全部通过，目录复用基准另行通过。

## 2026-10-23：搜索取消与后续优化优先级

上轮留下的搜索取消问题已复现并修复。`NativeAppModel` 原先取消 Swift 任务后只丢弃旧结果，已经进入 `LocalBlogStore.search` 的同步查询仍占用存储 actor。新输入的搜索、文章读取和其他存储请求会继续等待旧查询。

现在搜索在 `prepare()` 前检查取消，排队期间已过期的请求直接退出。搜索 SQL 显式开启只读查询取消；SQLite 每约 1,000 条虚拟机指令检查当前任务，并在每次结果读取前后检查，抛出 `CancellationError`。进度回调限定在该查询期间，退出时移除，嵌套查询保留外层回调；普通查询和保存事务不默认开启取消。可取消查询拒绝写语句。API 依据：[SQLite Query Progress Callbacks](https://www.sqlite.org/c3ref/progress_handler.html)。这不是中止所有磁盘等待的硬实时保证，SQLite 内部函数和系统 I/O 仍可能延迟到下一次回调。

新增 `SearchCancellationTests` 三条回归，可通过 `LEON_BOOK_TEST_FILTER=SearchCancellationTests` 运行测试二进制：

- 已取消的请求不创建数据目录；同一个 store 的新搜索仍能正常执行。
- 使用实际 FTS 表和实际搜索入口，构造 1,600 篇、每篇重复 300 次检索词的文章。运行旧搜索后取消，立刻提交新查询，并核对取消类型和新结果 ID。修改前旧搜索仍完成，新结果等待 **73.859 ms**；修改后两次采样等待 **22.791 / 19.644 ms**。完整未取消查询分别为修改前 **81.295 ms**、修改后 **77.459 / 90.827 ms**，本轮改善的是过期任务占用，不代表所有搜索本身都加速。
- 聚合查询在第一次返回行之后、下一次 `sqlite3_step` 计算期间取消。修改前继续算完并返回第二行，约再等 **1.08 s**；修改后只返回第一行，取消到退出查询为 **0.066 ms**。取消后在同一连接、同一仍被取消的任务中继续执行普通事务和查询，验证回调清理及语句复用；这部分持久化恢复耗时另计 **5.690 ms**，没有混入查询中止耗时。

继续审查得到以下待优化项，本轮未改动它们：

1. **优先移走图片转换的主线程工作。** `RichArticleEditor.Coordinator` 的 `pasteImage` / `chooseImage` 在主线程调用 `RichArticleClipboard.imageDataURL`，执行位图解码、PNG 编码、Base64 转换；替换图片还同步读文件。提取当前转换函数的原样代码，用 `swiftc -O` 临时基准测试 3,200 × 2,400 的合成 TIFF（30,722,130 字节），三次主线程调用耗时 **135.878 / 94.877 / 79.994 ms**。建议主线程只取得剪贴板数据和选择位置，将文件读取及转换移到有并发限制的后台任务，插入前校验文档和请求是否仍有效。该数值是转换函数耗时，不是整次粘贴或帧率测量。
2. **富文本媒体读取需要限流与请求合并。** `RichArticleMediaHandler` 每个请求都单独启动 `Task.detached`，完整读取原图；取消外层任务不会取消这个文件读取。同图重复出现、快速换页、多张大图时仍有多余 I/O 和内存占用的可能。应先测峰值内存，再为同文件的进行中请求去重、限制并发并跳过已取消的排队请求，保留原图质量。暂无峰值内存收益数字。
3. **关系面板按需求加载并复用身份索引。** `displayArticle` 无条件启动附加信息加载，关系面板隐藏时也会执行 `allArticleSummaries` 并重建 `NativeArticleLinkIdentityIndex`。取消检查在摘要查询前后，查询本身尚未开启取消。优先测大库切换文章的实际等待，再决定按面板显示加载及索引版本缓存。
4. **阅读计数的 JSON 导出仍位于打开文章的等待路径。** `incrementArticlePageViews` 每次阅读都会完整编码并原子写入文章和草稿两份 JSON，然后才返回文章。包含大段内嵌图片的 HTML 会放大该成本。可测量长文的文件写入量和打开耗时，再考虑合并导出；SQLite 计数、备份、退出和恢复时的数据一致性必须保留。`rebuildIndex()` 当前只是检查标记文件，不应误认为它还在重建全库索引。

所有测量使用临时数据；没有启动游戏。基准受机器负载和数据分布影响，测试断言取消行为与结果正确性，毫秒值只用于比较观察。

验证结果：新增三条回归单独通过；完整原生回归 **176 项通过、1 项失败**。失败为 `testRichArticleCaretMatchesTextAndPreservesEditing` 的“折叠文字选区应显示光标”断言，独立复测仍失败；该测试直接加载离屏编辑器，不调用本轮修改的存储搜索。上轮失败的白板离线初始化测试本轮已通过。8 组模块测试、存储检查及 `git diff --check` 通过。全量测试受其他同时运行的工作影响，FTS 新查询等待为 38.973 ms，聚合查询取消为 0.062 ms；行为断言仍全部通过，前文保留针对性运行的数值。
