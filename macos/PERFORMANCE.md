# LeonBook 性能基线与预算

更新日期：2026-08-30。基线设备为 Apple Silicon `arm64`、Swift 6.3.3。所有验证均通过命令行测试与构建完成，不启动应用。

## 测量方法

```zsh
macos/scripts/test-app.sh
macos/scripts/benchmark-performance.sh
macos/scripts/build-app.sh
```

`benchmark-performance.sh` 使用 Release 优化级别运行三组 10,000 条数据基准：文章投影、智能集合公式汇总、微博时间戳跨投影复用。文章过滤逐轮交替运行改造前算法与当前投影算法，并在相邻轮次交换先后顺序，避免缓存预热固定偏向某一实现。过滤与公式汇总报告四次采样中的最短值；投影建立记录一次完整建立，随后在旧投影仍存活时建立新投影并读取进程 RSS 增量模拟重建峰值。绝对耗时和内存用于本机回归，算法前后比值用于跨机器判断。

## 改造前基线

| 项目 | 基线 |
| --- | ---: |
| 调试冷构建 | 16.63 s |
| 完整测试与检查 | 25.02 s，59 个单元测试通过 |
| 10k 文章、无筛选派生一次 | 31.721–57.157 ms |
| 10k 文章、FTS 等待期同步摘要搜索一次 | 62.584–74.651 ms；修复前投影路径曾达到 180.908 ms |
| 10k 文章、FTS 已解析搜索派生一次 | 32.503–40.064 ms |
| Release 全目标构建 | 136.91 s 后失败：测试 target 的 `@testable` 被误编入打包流程 |

旧文章列表即使没有搜索词，也会为每篇文章拼接标题、分类、摘要和标签，再做 Unicode 大小写与变音折叠。SwiftUI 同一轮更新又会为标题计数、空状态、标签栏和布局分组多次读取该结果。微博标签、月份和时间线也会在每次 `body` 求值时重新扫描。

## 性能预算

| 场景 | 目标 |
| --- | ---: |
| 10k 文章投影建立 | < 500 ms，并且不占用主线程 |
| 10k 文章投影重建峰值 RSS 增量 | < 128 MiB（旧、新投影同时存活） |
| 10k 文章、无筛选单次派生 | < 1 ms |
| 10k 文章、FTS 等待期主线程派生 | < 8 ms，不在主线程扫描摘要 |
| 10k 文章、后台摘要匹配 | < 50 ms，可取消 |
| 10k 文章、FTS 已解析搜索单次派生 | < 8 ms |
| 10k 文章、算术公式汇总 | < 80 ms |
| 10k 文章、日期公式汇总 | < 120 ms |
| 10k 已解析微博时间戳进入时间线投影 | < 120 ms |
| 文章投影摘要存储 | 每篇摘要仅保留一份，其他结构只保存整数索引或派生文本 |
| 同一文章库页面更新 | 最多过滤一次、分组一次 |
| 智能集合大表 | 按滚动位置惰性创建行，汇总行接近可见时才求值 |
| 功能回归 | 全部单元、模块、原生结构和存储检查通过 |
| Release 打包 | 只构建 `LeonBook` 产品并成功生成签名应用包 |

## 当前结果

| 项目 | 当前值 | 相对基线 |
| --- | ---: | ---: |
| 10k 文章投影建立 | 134.255–254.178 ms，后台任务 | 达标 |
| 10k 文章投影重建峰值 RSS 增量 | 4.609–16.938 MiB | 低于 128 MiB 预算至少约 86.8% |
| 10k 文章、无筛选单次派生 | 0.002 ms | 至少约 15,800×，降低 >99.99% |
| 10k 文章、FTS 等待期主线程派生 | 0.002 ms | 不扫描文章，降低 >99.99% |
| 10k 文章、后台摘要匹配 | 28.735–35.735 ms（本轮 28.854 ms） | 达标，且不阻塞主线程 |
| 10k 文章、FTS 已解析搜索单次派生 | 0.972–1.120 ms | 至少约 29×，降低 >96% |
| 10k 文章、算术公式汇总 | 60.623 ms | 从 136.318 ms 降低约 55.5% |
| 10k 文章、日期公式汇总 | 45.751 ms | 从 886.615 ms 降低约 94.8% |
| 10k 已解析微博时间戳进入时间线投影 | 24.211 ms | 从 347.240 ms 降低约 93.0% |
| 自动化回归 | 66 个单元测试 + 7 组模块测试 + 原生/存储检查 | 全部通过 |
| Release 应用打包 | 71.96–129.57 s，签名与校验通过 | 从全目标构建失败恢复为成功 |

当前投影仅在文章或微博数据变化时重建。无筛选文章列表直接返回底层数组；普通输入先在可取消的 `Task.detached` 中匹配预先规范化的摘要，非 debounce 刷新则直接请求 FTS，避免串行等待本地扫描；FTS 已完成时只按 slug 集合匹配。标签、文件夹、状态、最近文章、微博标签、月份和时间线都复用已建立的索引。文章投影只保留一份完整摘要，slug 和状态统计使用整数索引或计数；统一的重建协调器以 generation 防止较旧投影覆盖新数据，确定性 barrier 测试覆盖重建期间的浏览量合并。

智能集合公式复用有上限的分词缓存、日期解析缓存和线程安全的日期格式器缓存；Property 与公式键优先走精确字典/字符串匹配，仍保留大小写不敏感兼容路径。汇总改为流式聚合，不再为每组文章分配完整值数组。大表从整组 `Grid` 改为惰性行栈，初始展示不再实例化全部单元格。共享时间戳缓存让微博 facet、时间线和其他消费者复用 ISO8601 解析结果；微博分页仍先提交首屏，再刷新全量 facet，且时区或区域设置变化会主动失效依赖日历的投影。

## 回归判定

- Release 基准超过任一绝对预算，或者新算法没有分别比旧算法快 90%（无筛选）、25%（后台摘要匹配）和 50%（已解析搜索），视为性能回归。
- 10k 算术公式超过 80 ms、日期公式超过 120 ms，或已解析时间戳进入时间线投影超过 120 ms，视为性能回归。
- 基准脚本是显式运行项，不放进普通测试，避免日常功能测试受机器负载影响。
- 冷构建耗时受 Swift 编译缓存影响，只记录趋势；运行时对照始终使用同进程的旧/新算法结果。
